This guide describes the current source code and the checks performed during
implementation. It covers application.py, main.py, watermark.py, detection.py,
requirements.txt, tester.py, tester_runner.py, and the HTML templates.


1. PURPOSE
==========

The service adds a basic machine-detectable watermark to one uploaded file, or
checks a file for the same watermark. Users switch between watermark mode and
detection mode in the browser.

The watermark is a fixed 64-bit pattern used by this project. A positive result
means the detector recognized that pattern. It does not establish ownership,
prove that the file came from a particular server, or determine whether its
content was generated by AI.


2. SUPPORTED FILES
==================

Category       Formats                 Accepted extensions
-------------  ----------------------  ----------------------------------------
Images         PNG, JPEG               .png, .jpg, .jpeg
Audio          M4A, MP3, WAV           .m4a, .mp3, .wav
Video          MP4, AVI, MOV           .mp4, .avi, .mov
Video          MPEG-2                  .mpg, .mpeg, .mpeg2, .mpeg-2, .m2v

Extension checks are case-insensitive. For example, .PNG is accepted.
An accepted extension does not guarantee that a damaged or mislabeled file can
be decoded. Images are checked against their expected PNG/JPEG format when
watermarking; audio and video must be readable by FFmpeg.


3. PROJECT FILES
================

application.py
    Imports the Flask app from main.py and exposes it as the WSGI object named
    application. It does not start a server when run directly.

main.py
    Defines the Flask app, routes, upload validation, processing calls,
    downloads, local assets, upload-request limit, and detection-result redirects.
    It keeps one watermarked upload in memory using temp_file and original_name.

watermark.py
    Embeds the image, audio, and video marks. Also contains the shared detection
    implementation, format lists, media helpers, and WatermarkError exception.
    Can be run directly to create a watermarked copy of a local file.

detection.py
    Provides the dedicated detection interface for bytes and local files. It
    calls watermark.py's existing detector so both modes use the same checks.
    Can also be run directly to check a local file.

tester.py
    Runs automatic checks with generated sample files, local Flask requests,
    configuration validation, and optional JSON reporting. See Section 11.

tester_runner.py
    Starts website-triggered checks in a separate background process. It manages
    temporary progress/results, one active run per instance, and the time limit.

requirements.txt
    Lists the third-party Python dependencies:
      Flask                  Web routes, requests, responses, and templates.
      Pillow>=10.0           Image decoding, orientation, and saving.
      numpy>=1.24            Pixel arrays and audio signal calculations.
      imageio-ffmpeg>=0.6.0   Locates FFmpeg for audio/video processing.
    Flask is unpinned; the other entries specify minimum versions. This is not
    a complete dependency version lock.

.platform/nginx/conf.d/client_max_body_size.conf
    Sets the Elastic Beanstalk nginx request-body limit to 501M, matching the
    Flask limit. This file must be included in a new deployment to take effect.

templates/base.html
    Shared page layout, header, navigation, and local stylesheet link. Every
    content page inherits this layout directly or through detectionMode.html.

assets/style.css
    Shared typography, panels, buttons, responsive layout, and background style.

assets/Black and Blue Background with Wavy Lines - Pawel Czerwinski.png
    The original image used as the full-page background on every page.

templates/insert.html
    Watermark-mode upload form and button to open detection mode.

templates/postWatermark.html
    Successful watermarking page with the download button.

templates/unsupportedFile.html
    Unsupported-type page used by watermark mode, with a retry link.

templates/detectionMode.html
    Detection upload form and inline upload errors. Also supplies the shared
    layout for the two result pages through Jinja template inheritance.

templates/watermarkFound.html
    Displays the positive detection result.

templates/watermarkNotFound.html
    Displays the negative detection result.

templates/testerMode.html
    Displays automatic tester controls, progress, results, and JSON report links.

Both result pages include links to check another file and return to watermark
mode. All pages use the same layout, typography, panels, buttons, and navigation,
with the supplied black-and-blue image as the background. Flask serves the
stylesheet and image locally from /assets/; external W3.CSS is not required.


4. INSTALLATION AND LOCAL STARTUP
================================

The source uses Python 3.10+ syntax. Implementation checks used Python 3.12.
Install Python and confirm that the python command works before proceeding.

In Windows PowerShell:

    cd "C:\Users\PNF40\.vscode\ece-30861\Version_0.3"
    python -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv\Scripts\python.exe main.py

Open http://127.0.0.1:5000/ in a browser. The root page sends you to /insert.
Press Ctrl+C in the terminal to stop the server.

Using the virtual environment's Python directly avoids needing to activate it
in PowerShell. Use that same interpreter for the command-line examples below.

Audio/video processing requires an FFmpeg executable available through
imageio-ffmpeg. Its Windows wheel normally includes the executable. A different
compatible executable can be selected with the IMAGEIO_FFMPEG_EXE environment
variable if needed.

main.py starts Flask with debug=True. This startup configuration is for local
development. application.py supplies a WSGI entry point, but the project does
not configure a production server.

Elastic Beanstalk upload limit:
    Both watermarking and detection accept files up to 500 MiB (524,288,000
    bytes), including a 500 MB file measured as 500,000,000 bytes. The total
    request-body limit is 501 MiB (525,336,576 bytes), with 1 MiB for multipart
    form data so that a file exactly at the 500 MiB cap is accepted.

    main.py sets MAX_FILE_SIZE to 500 * 1024 * 1024. Both upload routes enforce
    this cap before media processing. Flask MAX_CONTENT_LENGTH is MAX_FILE_SIZE
    plus 1024 * 1024. The nginx configuration in
    .platform/nginx/conf.d/client_max_body_size.conf sets
    client_max_body_size 501M; for the default nginx proxy on Amazon Linux 2
    and Amazon Linux 2023.

    Include .platform at the root of the deployment ZIP, alongside
    application.py and requirements.txt, and deploy a new application version.
    Do not place a containing Version_0.3 folder above those files in the ZIP.
    Confirm the dot-prefixed .platform folder was included when packaging.

    Change the file cap and both request limits, keeping the multipart allowance,
    and redeploy if a different size is needed. An
    environment using Apache needs its own proxy configuration instead.
    AWS reference:
    https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/platforms-linux-extend.proxy.html


5. BROWSER WORKFLOWS
====================

Add a watermark:
    1. Open /insert, labeled Watermark mode.
    2. Choose one supported file and select Add watermark.
    3. The service processes the uploaded bytes and displays postWatermark.html.
    4. Select Download to save the marked file under the uploaded filename.

The browser download contains the processed file. Processing does not replace
the original file selected on the user's computer.

Detect a watermark:
    1. Select Detect watermark on the watermark-mode page.
    2. On /detection, choose one supported file and select Detect watermark.
    3. The detector returns True or False.
    4. A successful check redirects to /detection/found or /detection/not-found.
    5. Select Check another file to repeat the check, or Back to watermark mode.

Invalid or unreadable files remain on the detection form with an error. They
are not reported as files with no watermark. Detection leaves the previously
watermarked download intact.


6. WEB ROUTES
==============

Path                     Methods    Behavior
-----------------------  ---------  -------------------------------------------
/                        GET, POST  Redirects to /insert using HTTP 302.
/insert                  GET        Displays the watermark upload form.
/insert_submit           POST       Validates and watermarks one uploaded file.
/download                GET        Downloads the latest marked file in memory.
/detection               GET        Displays the detection upload form.
/detection               POST       Checks one file and redirects on success.
/detection/found         GET        Displays watermarkFound.html.
/detection/not-found     GET        Displays watermarkNotFound.html.
/tester                  GET        Tester controls or the run selected by ?run=ID.
/tester/run              POST       Starts full/quick checks and redirects to status.
/tester/report/<run_id>   GET        Downloads the run's current JSON summary.

There are ten application URL paths; /detection supports two explicit request
methods. Flask also provides /assets/<path:filename> for the local stylesheet
and background image.
Upload forms use multipart/form-data with the file field named user-file.

A valid detection POST returns HTTP 303 so the result page is opened with GET.
The two result URLs display their respective messages; they do not store a
result history, filename, or an authenticated record of a completed check.

Watermark-mode failures:
    Missing/multiple uploads or a missing filename return HTTP 400.
    Unsupported extensions display unsupportedFile.html with HTTP 400.
    Processing failures return a plain-text error with HTTP 400.
    /download returns HTTP 400 when there is no processed file available.

Detection-mode failures:
    Missing/multiple uploads, unsupported types, and processing failures display
    detectionMode.html with an error and HTTP 400. No result redirect occurs.

Oversized requests:
    Both modes return HTTP 413 above the file or request limit. Flask supplies a
    readable message when it handles the rejection. nginx may reject the
    request first and display its own HTTP 413 error page.


7. PYTHON INTERFACES
====================

watermark.watermark_bytes(data: bytes, filename: str) -> bytes
    Creates and returns marked media bytes. filename supplies the format
    extension. Empty, unsupported, or unprocessable inputs raise WatermarkError.

watermark.watermark_file(input_path, output_path) -> pathlib.Path
    Writes a marked copy and returns its output Path. Input and output must use
    the same extension, except .jpg and .jpeg may be interchanged. The function
    refuses to replace the input or overwrite an existing output. Existing
    outputs raise FileExistsError; local file-access errors can raise OSError.

watermark.has_watermark(data: bytes, filename: str) -> bool
    Shared detector used by detection.py. Checks decoded content without needing
    an original, unwatermarked reference file.

detection.detect_watermark_bytes(data: bytes, filename: str) -> bool
    Returns True if the service's pattern is found, or False if it is absent.
    Empty, unsupported, or undecodable files raise WatermarkError.

detection.detect_watermark_file(file_path) -> bool
    Reads and checks a local file without modifying it. Returns the same boolean
    result as the bytes interface. File-access errors can raise OSError.

WatermarkError is defined in watermark.py and inherits from ValueError. Handle
errors separately from False so a file that could not be checked is not treated
as a negative result.

Example, run from the project folder with a real sample.png file:

    from detection import detect_watermark_file
    from watermark import WatermarkError, watermark_file

    try:
        output = watermark_file("sample.png", "sample_watermarked.png")
        found = detect_watermark_file(output)
        print("Watermark found" if found else "No watermark found")
    except (WatermarkError, OSError) as error:
        print(f"Could not process the file: {error}")

Use a new output filename if sample_watermarked.png already exists.


8. COMMAND-LINE USE
===================

Create a marked copy:

    .\.venv\Scripts\python.exe watermark.py "sample.png" "sample_watermarked.png"

Check a file:

    .\.venv\Scripts\python.exe detection.py "sample_watermarked.png"

The detector prints exactly one of these messages for a valid check:

    Watermark found
    No watermark found

Detection exits with code 0 for either valid result, and code 2 for caught file
or processing errors. A negative result is not an execution failure. For a
boolean value in Python code, use the detection functions rather than the
command's exit code.

The watermark command exits with code 0 on success or 1 for caught processing
and file errors. Both command-line parsers use code 2 for argument errors.


9. HOW THE WATERMARK WORKS
==========================

The shared identifier is the 64-bit hexadecimal value a6d35c9e71b48f02.

Images:
    The bits become an opaque black-and-white 8-by-8-cell pattern in the top-left
    corner. Cells are one to four pixels wide depending on image dimensions, so
    the complete mark is at most 32 by 32 pixels. Marking requires at least an
    8-by-8-pixel image. EXIF orientation is applied before marking. PNG
    transparency outside the mark is preserved; JPEG is saved at quality 95.

    Detection reads cell brightness at the four possible cell sizes. It accepts
    at least 62 of 64 matching bits with sufficient black/white contrast, allowing
    minor compression damage.

Audio:
    The 64 bits are mixed into the first 1.28 seconds as 20-millisecond symbols
    using 1200 Hz and 2200 Hz tones. Processing uses 48 kHz, 16-bit PCM. Existing
    carrier components are reduced before the tones are added. Short clips are
    padded to fit the sequence, and the result is encoded back to its format.

    Detection decodes the first 1.28 seconds, averages the channels, and compares
    energy at the two carrier frequencies for each symbol. All 64 bits must
    match, with minimum energy and separation from the alternate frequency.

Video:
    The image pattern is drawn on every frame. Detection checks only the first
    decoded video frame. The first video stream and optional first audio stream
    are retained; other streams are not mapped to the output. The retained audio
    is re-encoded but does not receive a separate audio watermark.

    Output encoding:
      MP4/MOV     H.264 video and AAC audio.
      AVI         MPEG-4 video and MP3 audio.
      MPEG-2      MPEG-2 video and MP2 audio at 25 video frames per second.
      M2V         MPEG-2 video only, at 25 frames per second.

    Odd video dimensions are padded by at most one row or column for encoding.


10. CURRENT LIMITS AND DATA HANDLING
====================================

- The marks are simple and removable. Image/video patterns are visible; audio
  tones may be audible. Cropping, trimming, resizing, or further compression can
  damage detection. A negative result does not prove that a file was never
  watermarked or that it was created by a human.
- The service recognizes its fixed pattern, not arbitrary third-party marks.
  It does not use a secret key, per-user identifier, or cryptographic signature.
- PNG/JPEG inputs are treated as still images. An animated PNG becomes a still
  image. Audio/video are re-encoded, which can change quality and file size.
- Each watermark upload clears the previous download before validation, even
  when the replacement upload fails. Server restarts also clear the download.
- Download bytes and filenames are process-wide globals shared by all clients,
  with no per-user isolation. This implementation assumes one file at a time.
- Audio/video helpers use temporary directories for processing and clean them
  up afterward. The web app keeps the final watermark-mode output in memory;
  it has a 500 MiB file limit, a 501 MiB request limit, and no database or
  persistent upload history.


11. AUTOMATIC TESTER
====================

Website mode:
    Select Automatic tester from the watermark or detection page. Choose Full
    or Quick and select Run automatic tester. The status page refreshes every
    two seconds while running, then shows the outcome, counts, elapsed time,
    and expandable output. A completed run's JSON summary can be downloaded.
    Links back to watermark and detection modes remain available.

    Website runs use a separate subprocess, preserving the live app's Flask
    settings and current download. Only one run is active per server instance,
    with a 180-second deadline. Reports and status use temporary files shared
    by workers on that instance. They are not durable or shared across multiple
    Elastic Beanstalk instances; a request reaching another instance may not
    find the run. Redeploy the updated Python files and templates to enable it.

tester.py provides a repeatable local check of the application using generated
sample files. No running web server or extra testing dependency is needed.
Run from the project folder after installing requirements.txt:

    .\.venv\Scripts\python.exe tester.py

The default full run covers all 14 accepted extensions, original-negative and
marked-positive detection, bytes/file APIs, unchanged original files, PNG
transparency, JPEG recompression, short-audio padding, video frames and optional
audio, web navigation, watermark downloads, detection redirects, invalid uploads,
command-line behavior, and upload limits.

The upload-limit checks compare the configured 500 MiB file / 501 MiB request
limits with the nginx configuration. Exact-boundary acceptance and rejection
are tested with a scaled file cap; this is not a 500 MiB load test or a check
against the live Elastic Beanstalk environment.

Options:

    .\.venv\Scripts\python.exe tester.py --quick
        Runs image, web, configuration, and command-line checks without
        audio/video checks or FFmpeg execution.

    .\.venv\Scripts\python.exe tester.py --report test-report.json
        Also writes a JSON report with the selected mode, outcome, test counts,
        elapsed time, and failure details. The named report is replaced if it
        exists; its parent directory must already exist.

The two options can be combined. Exit status is 0 if all checks pass, 1 if a
check fails or errors, and 2 for setup, argument, or report-writing errors.
Test counts describe groups, including additional per-format subcases.

The tester uses temporary samples and restores Flask configuration and download
variables after its web checks. It does not read or modify your own media files
or make live AWS requests. Full mode reports missing FFmpeg functionality as
an error rather than silently skipping media checks.


12. TROUBLESHOOTING AND VERIFICATION
====================================

Missing Python package:
    Install requirements with the same virtual-environment interpreter used to
    run main.py. Installing packages into another environment will not help it.

FFmpeg/media processing error:
    Confirm imageio-ffmpeg is installed and the source file opens normally.
    Check server logs for detection errors. If an executable override is used,
    confirm IMAGEIO_FFMPEG_EXE points to a compatible FFmpeg executable.

Unsupported file type:
    Compare the extension with Section 2. Renaming an unsupported file does not
    convert its media format.

HTTP 413 / request too large on Elastic Beanstalk:
    Confirm .platform/nginx/conf.d/client_max_body_size.conf was included at the
    deployment ZIP root and that the new version was deployed. Run sudo nginx -t
    on the instance to validate the configuration; sudo nginx -T displays the
    active settings. Confirm client_max_body_size 501M; to allow a 500 MiB file
    plus multipart form-data overhead.

No file available to download:
    Submit a valid file in watermark mode. A restart or another watermark
    upload may have cleared the earlier output.

No watermark found after editing:
    Check the untouched watermarked download first. The visual detector expects
    the top-left pattern; audio detection expects the sequence at the start.

Page styling/background:
    Include templates/base.html, assets/style.css, and the original background
    PNG when deploying. Confirm /assets/style.css and the image's /assets/ URL
    load successfully. Keep the image filename unchanged and refresh the browser
    cache if an earlier style is still displayed.

Checks completed during implementation:
    Original-negative and marked-positive detection for PNG, JPEG, M4A, MP3,
    WAV, MP4, AVI, MOV, and MPEG-2; watermark upload/download; detection booleans;
    both HTTP 303 result redirects; invalid, empty, and multiple uploads; mode
    navigation; local-file detection; command-line outputs; and retained
    downloads while using detection mode.

These checks used sample/generated media. They are not a guarantee that the
basic watermark will survive every content type, transformation, or encoder.
